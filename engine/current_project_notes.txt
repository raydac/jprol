- Variable snapshots share their array when nothing is bound, and reset writes only variables that changed.

- TermVar has no generated uid. Clones and snapshots tell variables apart by instance. Anonymous variables share the name "_".

- A context is not thread-local. `async/1` proves on a copy built before the task starts. Flag caches (`verify`, `trace`, share-knowledge-base, unknown, max prove depth) stay on that instance and are not volatile.

## 2. Architecture & Technical Discoveries
- `jprol-core` depends on `java-prolog-parser:2.3.0` (sibling project, Unicode code-point tokenizer). Run `mvn22 install` in the parser before building jprol after parser changes.
- `setEditable` rebuilds the text view tree (`BasicTextUI.modelChanged`). Call it only on the event thread. The script thread posts dialog enable/disable and reads the source text before the thread starts. Message and dialog output still go through concurrent queues drained by the Swing timer.
- User-clause bindings are applied on a clone first. The live goal is unified after a rule body succeeds, so a snapshot reset between those steps does not drop the body bindings.
- Ground facts (InMemoryItem.isFact) can be returned as the stored term. Non-ground clauses are still copied so each attempt has fresh variables. Ground facts are safe to share across fork threads because unify binds the query, not the stored fact.
- First-argument index is per name/arity, rebuilt after assert, retract, abolish, and clear. Clauses whose first argument is a variable stay in a wildcard bucket and are merged in source order.
- An atom and a zero-arity structure with the same functor text share one index bucket, because they unify.
- Integer and float values do not unify across classes, so they are indexed separately.
- Async copies share the root named-lock map. lock/1 blocks, trylock/1 does not, and the same thread must unlock once per lock.
- Changing one predicate does not drop another predicate's first-argument index. The cached index is a snapshot taken while that predicate's epoch stayed still.
- Variable identity is the instance. Clone maps are identity maps. A snapshot's visited set scans up to 16 variables, then switches to an identity hash map. TermVar.equals and hashCode follow the instance.
- `==` follows the canonical unbound variable first, so aliases compare equal. Distinct anonymous variables still use the identity hash, then a weak identity order. Named variables with the same text still compare equal.
- `\+` and `not/1` prove the goal, then `discardBindings()`. `catch/3` does the same before unifying the frozen ball, and rethrows when the catcher does not match. `throw/1` keeps the term (an atom stays an atom). Built-in balls are `error(Formal, Context)`.
- `->` commits by skipping only the surrounding `;` choice point. Cuts in the condition stay on the condition's own root.
- `retract/1` walks a snapshot cursor (`RetractCursor`). Clause search copies the live list, and `retract((Head :- Body))` matches the body (`true` for a fact). `c(X), retract(c(X))` therefore yields every clause that existed when the scan started.
- `mod/2` takes the sign of the divisor. Integer `+`, `-`, `*` raise `evaluation_error(int_overflow)` instead of wrapping. Prefix `+`/`-` are `200 fy`, the same row as `\` in the SWI operator table, so `-7 mod 3` is `(-7) mod 3`.
- `length/2` with both arguments unbound enumerates 0, 1, 2, ... `between/3` is a Java generator. List length and variable-snapshot walks follow the list spine in a loop.

## 3. Technical Debt & Refactoring
- Backtracking still restores a full variable snapshot. A trail of only the bindings made since the choice point would avoid the scan on goals with many variables.
- Rules still clone the goal and the clause on every attempt.
- Library predicate lookup walks the library list until the processor is cached on that structure instance.
- `TermStruct.stream()` chains `Stream.concat` recursively on 2-arg structs (including `TermList` spines), making `.variables()` quadratic on long lists when exposed at the root goal; `TermList.cloneAndReplaceVariables` and `makeClone` are also recursive along the list spine.

## 5. Known Issues & Limitations
- First-argument index groups every non-empty list under one bucket. Matching lists still need a full unify.
- The index is not used below 8 clauses. Those predicates only get the cheap first-argument rejection.
- `testDeepRecursion` stays disabled. The prove loop is iterative, and `max_prove_stack_depth` is 10000 frames (about 5000 Prolog calls, two frames each). `count(0, 100000)` and a 10000-element recursive sum exceed that cap. Last-call optimization is not implemented.

## 6. Open Questions & Pending Decisions
