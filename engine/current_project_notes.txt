## 1. Implementation Progress
- SpotBugs `check` is clean for the reactor. Real defects are fixed in code. Live engine and Swing objects that must be shared are listed in each module's `spotbugs-exclude.xml`.
- Project version is 3.2.0-SNAPSHOT (parent, modules, Windows file/product version 3.2.0.0, notepad stub).
- `changelog.txt` (repo root) has an unreleased 3.2.0-SNAPSHOT section.
- Prove loop in JProlChoicePoint reuses stack frames and returns plain result codes. No per-step frame, OptionalInt, or result object.
- Variable snapshots share their array when nothing is bound, and reset writes only variables that changed.
- In-memory clause search skips a copy of the query, reuses ground facts, rejects impossible first arguments before full unify, and indexes predicates with 8 or more clauses by first argument.
- TermStruct.cloneAndReplaceVariables clones each argument once.
- Named lock/1 is a counted reentrant mutex. unlock/1 reports a missing locker and a locker owned by another thread (`NamedLockOwnerException`, then permission_error). Disposing the root context wakes threads blocked in lock/1.
- `TermVar.isPresentedInVarChain` walks the immediate-value chain, bounded by `LOOP_WATCHDOG`.
- `TermStruct.getArguments` returns a copy. Clause lookup still returns the stored clause so ground facts stay shared.
- `asOperator` and `asOpContainer` return fresh parser objects. Context flags read across threads (`verify`, `trace`, share-knowledge-base, max prove depth) are volatile. `nextLong` uses an unsigned shift so `Long.MIN_VALUE` cannot stay negative.
- First-argument indexes are cached per predicate, and a cache entry is kept only when the clause set did not change while it was built.
- Graphics primitives repaint once per burst. dot/2 writes pixels directly. fillrectangle/4 draws on the caller thread. play_sound/2 writes the tone in chunks. graphics/2 reads the real height and resizes when either side changes.

## 2. Architecture & Technical Discoveries
- User-clause bindings are applied on a clone first. The live goal is unified after a rule body succeeds, so a snapshot reset between those steps does not drop the body bindings.
- Ground facts (InMemoryItem.isFact) can be returned as the stored term. Non-ground clauses are still copied so each attempt has fresh variables. Ground facts are safe to share across fork threads because unify binds the query, not the stored fact.
- First-argument index is per name/arity, rebuilt after assert, retract, abolish, and clear. Clauses whose first argument is a variable stay in a wildcard bucket and are merged in source order.
- An atom and a zero-arity structure with the same functor text share one index bucket, because they unify.
- Integer and float values do not unify across classes, so they are indexed separately.
- Async copies share the root named-lock map. lock/1 blocks, trylock/1 does not, and the same thread must unlock once per lock.
- Changing one predicate does not drop another predicate's first-argument index. The cached index is a snapshot taken while that predicate's epoch stayed still.

## 3. Technical Debt & Refactoring
- Backtracking still restores a full variable snapshot. A trail of only the bindings made since the choice point would avoid the scan on goals with many variables.
- Rules still clone the goal and the clause on every attempt.
- Library predicate lookup walks the library list until the processor is cached on that structure instance.

## 5. Known Issues & Limitations
- First-argument index groups every non-empty list under one bucket. Matching lists still need a full unify.
- The index is not used below 8 clauses. Those predicates only get the cheap first-argument rejection.

## 6. Open Questions & Pending Decisions
- Whether to replace the snapshot with an explicit trail. That changes when live variables become bound and needs the prove tests around it.
