## 1. Implementation Progress
- `ProlContextUncaughtException` keeps the live context. SpotBugs exposure warnings for that field are excluded, same as the other engine identity accessors.
- Dialog input is enabled and disabled on the Swing event thread. Each run has a session id, so a late disable from a finished run does not lock the next one. Declining the next solution no longer logs a halt stack trace. The dialog pane flushes at most 100 queued chunks per timer tick.
- SpotBugs `check` is clean for the reactor. Real defects are fixed in code. Live engine and Swing objects that must be shared are listed in each module's `spotbugs-exclude.xml`.
- Project version is 3.2.0-SNAPSHOT (parent, modules, Windows file/product version 3.2.0.0).
- GUI title and About read the Maven project version. `build-version.properties` is filtered at build time; the jar `Implementation-Version` is the fallback. Prolog `version_data` stays the hardcoded 3.1.1 flag in `JProlContext`.
- `JProlChoicePoint` reuses its `ProveStack` across `prove()` calls, builds named-variable maps lazily on demand (`findVar`/`findAllGroundedVars`), skips redundant first-attempt snapshot resets on fresh subgoals, peels right-nested `,` conjunctions without extra wrapper choice points when `trace` is off, and unlinks deterministic choice points from `prevCp` so deeper steps inherit smaller/unchanged snapshots.
- Non-ground facts unify directly against the live goal (rolling back via `discardBindings` on mismatch), while rule heads copy-on-write only subterms containing unbound variables (`GoalCloner`) and skip the post-body re-unification when the goal was ground.
- `VariableStateSnapshot` updates changed entries in place via array clone when new bindings contain no variables, accesses `TermStruct` arguments without defensive array clones, and traverses deep structures/lists iteratively on tail arguments.
- `PredicateInvoker` uses typed `invokeExact` `MethodHandle`s plus direct functional dispatchers for hot bootstrap/core predicates and evaluables; `AutoArgumentValidator` skips tautology specs (`?term`, `@term`, `-term`) and checks argument types without allocating exceptions on the fast path.
- `SmallIdentityVarMap` backs `TermVar.newVariableMap()` with a compact linear identity pair array (promoting to `IdentityHashMap` above 16 variables). `RhsItemComplex` checks shared-variable head compatibility via non-mutating `UnifyTrial` instead of cloning both clause head and query.
- `TermStruct` computes `structureSignature` lazily and reuses it across clones; `TermStruct.stream()`, `variables()`, and `findAllNamedVariables()` use iterative spliterators/stacks; `TermList` `makeClone`, `cloneAndReplaceVariables`, `unifyWith`, `isUnifiableWith`, `isGround`, `isUnground`, and `containsNamedVariable` walk list spines iteratively.
- `TermLong` and `TermDouble` compare and compute with unboxed primitives; `Terms` caches `TermLong` values in `[-128, 1024]`.
- `TermVar` has no generated uid. Clones and snapshots tell variables apart by instance. Anonymous variables share the name `"_"`. `setValue`, `tryGround`, `isGround`, and `findUngroundVariable` walk variable chains iteratively bounded by `LOOP_WATCHDOG`.
- Named `lock/1` is a counted reentrant mutex. `unlock/1` reports a missing locker and a locker owned by another thread (`NamedLockOwnerException`, then `permission_error`). Disposing the root context wakes threads blocked in `lock/1`.
- `TermStruct.getArguments` returns a copy. Clause lookup still returns the stored clause so ground facts stay shared, and `CopyOnWriteArrayList` clause lists iterate their immutable array snapshot directly.
- `asOperator` and `asOpContainer` return fresh parser objects. `nextLong` uses an unsigned shift so `Long.MIN_VALUE` cannot stay negative.
- A context is not thread-local. `async/1` proves on a copy built before the task starts. Flag caches (`verify`, `trace`, share-knowledge-base, unknown, max prove depth) stay on that instance and are not volatile.
- First-argument indexes are cached per predicate, and a cache entry is kept only when the clause set did not change while it was built.
- Changelog is `../changelog.txt` (jprol repo root, one level above `engine`).
- Graphics primitives repaint once per burst. `dot/2` writes pixels directly. `fillrectangle/4` draws on the caller thread. `play_sound/2` writes the tone in chunks. `graphics/2` reads the real height and resizes when either side changes.
- `ComplexPrologCornerCaseTest` (55 passing), `ChoicePointHotPathOptimizationTest` (7 passing), `ComplexPrologKnownIssuesTest` (15 passing, `testDeepRecursion` `@Disabled`), and `JProlIsoTest` (13 tests / 377 Prolog checks) cover engine semantics and hot-path invariants.
- Life example (`examples/java/jprol-example-life`): generations are computed on one daemon executor thread, then the swap and repaint run on the Swing event thread through `invokeAndWait`. `LifeGameField` guards both generation arrays with one private `ReentrantLock`.
- Notes reviewed and compacted after core prove-engine hot-path optimizations.

## 2. Architecture & Technical Discoveries
- `jprol-core` depends on `java-prolog-parser:2.3.0` (sibling project, Unicode code-point tokenizer). Run `mvn22 install` in the parser before building jprol after parser changes.
- `setEditable` rebuilds the text view tree (`BasicTextUI.modelChanged`). Call it only on the event thread.
- User-rule bindings are applied on a copy-on-write clone (`GoalCloner`) first; the live goal is unified after the rule body succeeds so a snapshot reset between body backtracking steps does not drop body bindings. Non-ground facts have no body, so they unify directly with the live goal and call `discardBindings()` if unification fails partway through.
- Ground facts (`InMemoryItem.isFact`) are returned as the stored term. Non-ground clauses are cloned per attempt with `SmallIdentityVarMap`.
- First-argument index is per name/arity, rebuilt after assert, retract, abolish, and clear. Clauses whose first argument is a variable stay in a wildcard bucket and are merged in source order. Atom and zero-arity structure with the same functor text share one index bucket; integer and float values are indexed separately.
- Child choice points derive their `VariableStateSnapshot` from the active tip (`rootChoicePoint.parentCp`) rather than always rescanning `rootChoicePoint.varSnapshot`, and deterministic choice points unlink themselves once completed so subsequent conjuncts share unchanged snapshot arrays.
- `==` follows the canonical unbound variable first, so aliases compare equal. Distinct anonymous variables use the identity hash, then a weak identity order. Named variables with the same text compare equal.
- `\+` and `not/1` prove the goal, then `discardBindings()`. `catch/3` does the same before unifying the frozen ball, and rethrows when the catcher does not match. `throw/1` keeps the term. Built-in balls are `error(Formal, Context)`.
- `->` commits by skipping only the surrounding `;` choice point. Cuts in the condition stay on the condition's own root.
- `retract/1` walks a snapshot cursor (`RetractCursor`). `retract((Head :- Body))` matches the body (`true` for a fact).
- `mod/2` takes the sign of the divisor. Integer `+`, `-`, `*` raise `evaluation_error(int_overflow)` instead of wrapping. Prefix `+`/`-` are `200 fy`.

## 3. Technical Debt & Refactoring
- Backtracking still restores a `VariableStateSnapshot` array rather than an explicit binding trail; an explicit undo trail could further reduce scan cost on goals with hundreds of simultaneously live unbound variables.
- Non-ground rule clauses still clone the stored rule AST (`clause.makeClone()`) on each matching attempt.
- Library predicate lookup walks the library list once until the `PredicateInvoker` is cached on that `TermStruct` instance.

## 5. Known Issues & Limitations
- First-argument index groups every non-empty list under one bucket. Matching lists still need a full unify.
- The index is not used below 8 clauses. Those predicates only get the cheap first-argument rejection.
- `testDeepRecursion` stays disabled. The prove loop is iterative, and `max_prove_stack_depth` is 10000 frames (about 5000 Prolog calls, two frames each). `count(0, 100000)` and a 10000-element recursive sum exceed that cap. Last-call optimization is not implemented.
